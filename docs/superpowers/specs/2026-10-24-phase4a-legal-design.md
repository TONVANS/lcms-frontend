## 1. Goal and scope

Rebuild the two Legal team apps inside LCMS, on mock data, at the same quality bar as GC. Live mode must work later without feature-code changes.

**4a covers:**
- the Legal sidebar;
- dashboard;
- regulations: list, detail, create/edit (modal + wizard), delete, file attachments and Drive links, CSV export;
- cases: list, detail, create/edit (modal + wizard), delete, CSV export, print;
- permission enforcement;
- the Home Legal card.

**Not in 4a:**
- procurement, the law library and hearings (4b, only if stakeholders confirm them);
- deadline alerts (the team tracks none);
- attachments on cases;
- a progress history for cases;
- importing the team's Google Sheets (Phase 5);
- currency conversion.

### 2.2 `LegalCase` (replaces the draft in Frontend_LCMS_Project.md §6)

| Field | Lao label | Type | Req. | Rules |
|---|---|---|---|---|
| `id` | — | `ID` | server | |
| `caseNo` [id] | ລະຫັດຄະດີ | string | server | generated by the mock server as `LC-<yyyy>-<nnn>`; read-only everywhere |
| `defendant` [defendant] | ຈຳເລີຍ | string | ✓ | 1–200 chars |
| `allegation` [party] | ຂໍ້ກ່າວຫາ | string | ✓ | 1–300 chars |
| `handlingUnit` [branch] | ພາກສ່ວນດຳເນີນ | string | ✓ | 1–200 chars, free text |
| `caseType` [caseType] | ປະເພດຄະດີ | `CaseType` (§2.3) | ✓ | |
| `stage` [status] | ສະຖານະຄະດີ | `CaseStage` (§2.3) | ✓ | default `first_instance` |
| `damage` [damageLak/Usd] | ມູນຄ່າເສຍຫາຍ | `DualAmount` | — | |
| `fine` [fineLak/Usd] | ມູນຄ່າປັບໄໝ | `DualAmount` | — | |
| `recovered` [recLak/Usd] | ມູນຄ່າທີ່ເກັບໄດ້ຄືນ | `DualAmount` | — | |
| `disputeDate` [lastDate] | ວດປ ເກີດຂໍ້ຂັດແຍ່ງ | `ISODate \| null` | — | not in the future (Q12 default: the date the dispute arose) |
| `progress` [progress] | ຄວາມຄືບໜ້າຄະດີ | string \| null | — | ≤ 2000 chars; overwritten on edit |
| `createdAt`, `updatedAt`, `createdBy` | — | server | | display only |

- **`DualAmount`:** `{ lak: number | null; usd: number | null }`.
  - Each value is ≥ 0, or null when not entered.
  - A case carries LAK and USD **at the same time**, so the single-currency `Money` does not fit.
- **Total** (ລວມທັງໝົດ) is `caseTotal(c) = damage + fine` per currency, with null treated as 0.
  - It is derived by a pure function in `features/legal/cases/lib/` and never stored.
  - The result is a `DualAmount` whose side is null when both inputs on that side are null.

### 2.3 Enumerations

The keys are English. The Lao labels live in `lo.legal.*` and follow the team's apps.

| Union | Keys → Lao |

  - `completed`: emerald;
  - `closed`: slate.
- `StatusBadge` shows a dot plus a label, so status is never shown by colour alone.

7. **New shared util `src/lib/utils/export-csv.ts`:** `toCsv(headers, rows)` and `downloadCsv(filename, csv)`.
   - UTF-8 BOM, CRLF line endings.
   - Every cell is quoted, with `"` doubled.
   - Cells starting with `= + - @` get a leading `'`, so a spreadsheet cannot run them as formulas.

## 4. Permissions (same model as GC)

| Action | Permission | UI | Mock handler |
|---|---|---|---|
| View lists, detail, dashboard | `view` | `ModuleGuard` | 401 / 403 |
| Create (modal, wizard, `/legal/new`), upload files | `create` | `Can` / `PermissionGuard` → `/forbidden` | 403 |
| Edit | `edit` | `Can` | 403 |
| Delete (ConfirmDialog, then a toast) | `delete` | `Can` | 403 |
| Download files, export CSV | `download` | `Can` | 403 on download |

- Export runs on the client. It is gated in the UI only, and it exports the **current filtered result set**.
- To get the full filtered set, export fetches every page through the service's `list` call with `pageSize: 'all'` (§7). The 100-row page-size cap does not apply to export.

## 5. Dashboard data (`GET /legal/dashboard`)

```ts
interface LegalDashboard {
  regulations: {
    total: number;
    byStatus: Record<RegulationStatus, number>;
    unitCount: number; // distinct units that have ≥ 1 regulation
    byType: { type: RegulationType; count: number }[]; // every type, zero counts included
    byUnit: { unit: LegalUnit; count: number }[]; // only units with count > 0, sorted desc
  };
  cases: {
    total: number;
    inProgress: number;
    finished: number;
    byStage: { stage: CaseStage; count: number }[]; // every stage, in workflow order
    damage: DualTotals;
    fine: DualTotals;
    recovered: DualTotals;
  };
}
interface DualTotals { lak: number; usd: number } // sums with null as 0
```

### 6.4 Create / Edit

- **One zod schema per entity** (`regulation.schema.ts`, `case.schema.ts`), shared by the modal and the wizard. Messages are in Lao, and server `fieldErrors` map onto fields (409 → `number`).
- **Edit** reuses the modal, prefilled.
- **Regulation form:**
  - DatePicker for `issuedDate`.
  - `year` pre-filled from it.
  - `typeOther` shown only when `type = other`.
  - Unit select.
  - Status select.
  - A repeatable "add Drive link" input.
  - In the wizard and the create modal, files are staged in `FileDropzone` and uploaded after create, using the GC wizard's lock and partial-failure toast.
  - On edit, files are managed on the detail page.
- **Case form:** three `DualAmount` rows (damage, fine, recovered), each with a LAK and a USD amount field.
  - They reuse `MoneyInput` with a single currency.
  - If `MoneyInput` cannot render a fixed single currency without a one-option select, the plan adds a `fixedCurrency` mode to it, with tests.
  - A live total row shows `caseTotal`.
- **Wizard `/legal/new`:**
  - The `?kind=regulation|case` query preselects the kind. Without it, step 0 is a two-card chooser (ນິຕິກຳ / ຄະດີ).
  - The page needs `create` (`PermissionGuard`).
  - Regulation steps:
    1. ຂໍ້ມູນທົ່ວໄປ: title, type, number, issuedDate, year
    2. ຄວາມຮັບຜິດຊອບ: unit, responsible, status, purpose
    3. ເອກະສານ ແລະ ກວດສອບ: links, files, review
  - Case steps:
    1. ຂໍ້ມູນຄະດີ: defendant, allegation, handlingUnit, caseType, stage, disputeDate
    2. ມູນຄ່າ: damage, fine, recovered, live total
    3. ຄວາມຄືບໜ້າ ແລະ ກວດສອບ: progress, review
  - A live summary aside, as in GC.
  - On success, the wizard redirects to the new record's detail page.

### 6.5 Detail pages

- **`/legal/regulations/[id]`:**
  - Header: number, title, status badge. Edit and Delete, permission-gated.
  - Info grid: every §2.1 field.
  - External links as an "open in new tab" list (`rel="noopener noreferrer"`).
  - `DocumentManager` with `entityType="regulation"` and the permissions from §4.
- **`/legal/cases/[id]`:**
  - Header: caseNo, defendant, stage badge. Edit and Delete.
  - Stage `Stepper`, read-only: ສານຂັ້ນຕົ້ນ → ສານຂັ້ນອຸທອນ → ຂັ້ນລົບລ້າງ → ສໍາເລັດ/ຈົບຄະດີ. The last step's label follows the actual finished stage.
  - Info grid.
  - Money table: rows damage / fine / total / recovered; columns LAK / USD.
  - Progress note.
- A 404 shows an `EmptyState` with a link back to the list.

### 6.6 Export and print

- **Regulations CSV:** `EDL_Legal_Regulations_<yyyy-mm-dd>.csv`.
  - Headers: ເລກທີ, ລົງວັນທີ, ຊື່ນິຕິກຳ, ປະເພດ, ປີນຳໃຊ້, ຈຸດປະສົງ, ຜູ້ຮັບຜິດຊອບ, ຫ້ອງການ/ຝ່າຍ, ສະຖານະ, ລິ້ງເອກະສານ.
  - Links are joined with `; `.
- **Cases CSV:** `EDL_Legal_Cases_<yyyy-mm-dd>.csv`.
  - Every case field, with LAK and USD in separate columns, and the derived totals included.
- **Print** on the cases list: a print stylesheet that hides the shell, filters and actions, and prints the current page of the table on a white background.
- Dates in exports use `dd/mm/yyyy`, and numbers are plain (no grouping), so spreadsheets parse them.
